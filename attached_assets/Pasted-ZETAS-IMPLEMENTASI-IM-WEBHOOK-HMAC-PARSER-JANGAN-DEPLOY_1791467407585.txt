IMPLEMENTASI HMAC:

Webhook harus mendapatkan raw HTTP body SEBELUM JSON parsing.

Signature harus dihitung berdasarkan:

AppKey + EXACT RAW MESSAGE BODY

kemudian:

HMAC-SHA256 menggunakan AppSecret

dan hasilnya:

lowercase hexadecimal.

Jangan parse JSON lalu stringify ulang body sebelum menghitung signature.

Gunakan constant-time comparison untuk membandingkan hasil signature dengan header Authorization.

Jika:
- Authorization tidak ada → reject
- verifier belum dikonfigurasi → tetap fail-closed
- signature salah → reject
- signature benar → baru lanjut parse payload

Pertahankan behavior fail-closed yang sudah ada.

PARSER:

Parser harus membaca struktur root:

seller_id
message_type
data[]

Untuk message_type = 19:

validasi:
- seller_id ada
- data adalah array
- setiap item memiliki sync_type
- session_id tersedia untuk Session Update

Hanya dukung:

sync_type = SESSION_UPDATE

Jangan menganggap sync_type/session_id berada langsung di root.

Jika payload malformed → HTTP 400.

Jika message_type tidak didukung → pertahankan behavior existing yang aman.

ROUTING:

- user_account_id sebagai user_id ZETAS
